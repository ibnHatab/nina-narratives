# Ownership and routing for the Book I experiment

The [maintainer's composition decision](https://github.com/ibnHatab/nina-narratives/blob/e98d5fe/notes/incarnation-composition.md) calls for one shared set of cognitive rules. Memory, event logs, principals and grants belong to each installation. The [cross-domain research agenda](https://github.com/ibnHatab/nina-narratives/blob/e98d5fe/notes/cross-domain-cognition.md) motivates the competition for attention in this experiment. Its news and office probes are deferred.

| Candidate specialist | Resource it owns | Proposed director contract |
|---|---|---|
| Situations | Source-tagged observations, possible explanations and disputes | Supply an identified observation from this installation. Carry its source, occurrence identity and decision epoch through routing. A late report can reopen an explanation. |
| Commitments | One lifecycle per promise instance and its referenced outing | Deliver scoped creation, renegotiation and completion evidence. A later promise to call the same person gets a fresh instance. |
| Attention | Allocation of a bounded opportunity across eligible tasks | Supply the current interruption opportunity. Resolve permission and critical-notice eligibility before discretionary allocation. |
| Speech delivery | Correlated commitment and acknowledgement | Require a grant for the principal, audience, task and channel. Return delivery or failure with the same request identity. A route to a speaker does not supply consent. |

The [home composition](https://github.com/ibnHatab/nina-live/blob/d01f10f27dba8590ef56fe795580a5afe76b7119/catalog/domains/composition.yaml) already uses a director and an interface for scene wishes. These rows propose comparable ownership boundaries for a future link. The candidate declares local finite task, trip and status types. Instantiating many outings requires a host identity mapping with a lifetime long enough for delayed and replayed reports. One reusable constant for every appointment would reintroduce the stale-return defect.

The existing [event envelope](https://github.com/ibnHatab/nina-live/blob/d01f10f27dba8590ef56fe795580a5afe76b7119/log/log.go) supplies sequence, time, stream, kind, key, cause, payload and version. Sequence can bound which reports Nina had received at commitment. A record sequence alone cannot establish that two deliveries represent the same real occurrence. The publisher and director need a stable occurrence key and an explicit task/outing correlation. On restart the host must restore both the evidence cursor and pending delivery identities. An acknowledgement lost after actual speech still leaves an ambiguous outcome unless the speaker supports durable idempotency.

The dry-run host has no home or office credentials. Connecting either incarnation would require an incarnation-local event publisher, scope and trust checks, and a director-mediated request/receipt interface. Share specialist code across incarnations. Keep each binding's experiences and pending requests local. Open architectural choices include who issues occurrence keys, which evidence can suppress a reminder, and whether failed or unknown delivery permits a retry.

Run `python candidates/responsive-household/check_boundary.py` with the installed Metis Python. Eight single-step exact projections test the standalone specialist. At unit weights, presenting completion and authorization together while a notice is queued gives a 0.5 marginal for commit. Delivering completion first and resolving the batch before issuing a grant is therefore a substantive director obligation. Reusing the same outing constant makes an old return sufficient to release a later promise with marginal 1. The specialist rejects a receipt for another task instance. These are kernel measures on deliberately constructed boundary states, independent of the responsive simulator's input sequencing.
